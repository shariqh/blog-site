The design failure was simpler than it looked: I was running three or four concurrent sessions and couldn't tell, at a glance, who owned what.

Copilot CLI was drafting documentation in one terminal, Claude Code refactoring a module in another, a third instance writing tests. My tool for managing them showed generic status cards with timestamps. Which agent was blocked waiting on me? Which had a plan I hadn't reviewed? Which had finished something worth acting on? The information existed somewhere in the app. It just wasn't organized around those questions.

That's the gap v1.2.1 closes.

## Design principles

The redesign started from a reference dashboard I'd been studying for months. The discipline was to translate its underlying principles, not copy its layout. A modular grid with precise column-and-gutter boundaries. Calm density: information readable at a glance without requiring hover. Cool graphite surfaces so the content, not the chrome, carries focus.

The color system has one hard rule: color encodes role, not status. Cyan marks agent activity. Yellow tracks plans. Green indicates outcomes. Pink (derived from the app icon) appears exclusively for human attention signals. That last constraint matters more than it sounds. If ambient agent activity could bleed into the attention color, you'd stop trusting it within a week. Pink means the agent is waiting on you, and nothing else earns that color.

Dark and light themes are both fully implemented, not one theme with an invert filter on the other. The layout reflows across window sizes without collapsing its information hierarchy. Focus order follows reading order so keyboard navigation doesn't jump around the screen.

## The Live Operations Desk

The main dashboard now reads as a real operations surface: active agents across the top, a "Needs you" count that's always the first thing visible, plans, outcomes, and an activity chart built from real spans rather than extrapolated trends.

The agent list handles a case I kept hitting: parent managers that spawn child agents. The 6/10 dot meter in the screenshot counts truthfully. Parent managers appear as lanes; their reported children are counted separately. The meter doesn't flatten the hierarchy or misrepresent the total. If a parent has three children, you see four dots for that cluster.

Ownership flow and live dispatch sit in the right panel. Recent outcomes appear below the activity chart. The layout is deliberate: information you act on most often sits top-left; ambient context fills the right and bottom. The activity chart tells you the system is working. It does not demand a response. Ambient activity never triggers the human-attention color.

## Action-first inbox



<Image src="/static/images/blog/agent-inbox-live-operations-desk/img2.png" alt="Dark Agent Inbox queue with three work rows and an open release-approval inspector containing action details and response buttons." />



The inbox inspector leads with next step — what the agent needs from you, stated plainly — before any background or context. The signed-release approval above puts the action first, then impact, then context, with response controls pinned to the bottom so they're always reachable regardless of how long the context section runs.

Keyboard focus is preserved across queue navigation. Moving between items doesn't reset your position in the inspector, and you can respond without touching the mouse.

## Distribution and the update chain

This release ships as a universal notarized macOS DMG (Apple Silicon and Intel in one file) and as separate x64 and arm64 AppImage and DEB packages for Linux. No Windows build; I'm not releasing something I don't run.

Getting the release transaction right took longer than expected. Assets are pinned to exact checksums before any client download starts. That sounds straightforward until you hit Ubuntu's APT mirror propagation lag: a client fetching from a stale mirror gets a different checksum than the pinned one, which looks like corruption when it isn't. The fix was to include the DEB in the AppImage distribution path and document mirror-pinning for CI consumers. The packaging benchmark was similarly unreliable until I moved it to a stable dedicated environment. Flaky benchmarks are worse than no benchmarks. They train you to ignore the signal.



The update check is new in v1.2.1 and is strictly check-and-notify. Nothing installs automatically.

The manifest covers five targets: macOS universal, Linux x64 AppImage, Linux arm64 AppImage, Linux x64 DEB, and Linux arm64 DEB. It's generated deterministically and signed over raw bytes with Ed25519 before publication. The signing key is pinned inside the client binary. The envelope format is built for key overlap. If I need to rotate or add a second signer before a release cycle ends, the client accepts multiple signatures and validates any one of them. A key rotation doesn't strand clients mid-cycle.

The daily check is opt-in. It hits GitHub's release API directly with no telemetry, no third-party update service, and no other network activity. I verified the full bootstrap path by running v1.2.0 and watching it detect the v1.2.1 manifest and surface the update in Settings.



<Image src="/static/images/blog/agent-inbox-live-operations-desk/img1.png" alt="Agent Inbox Settings Updates section showing Agent Inbox 1.2.1 available to the running 1.2.0 app." />



The Settings view above shows what a successful check looks like: current version, detected release, and the "Review release" action. Clicking through goes to the release page. You download manually from there. The check tells you something newer is available; it doesn't act on your behalf.

## Signal fidelity

Making operator software trustworthy is mostly about signal discipline, not the cryptographic layer. The signing matters; so does the color system, the count, the chart.

Every one of those constraints is cheap to violate and expensive to recover from. Once a user learns that the pink badge is sometimes just noise, they stop reading it. Once the agent count is wrong, they discount everything. The discipline is maintaining signal fidelity even when rounding the edges would be easier.

The v1.2.1 release and full source are open on GitHub; signed manifests and checksums for all five targets are on the releases page.
