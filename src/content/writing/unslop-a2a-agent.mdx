## Two copies of the same skill

I use a writing skill called unslop with two coding assistants, GitHub Copilot CLI and Claude Code. A skill is a file of instructions an assistant loads before it does a task. Unslop's instructions tell the assistant to edit out phrasing that reads as AI-written. I started from [Lauren Tan's unslop skill](https://github.com/cursor/plugins/blob/e8d856f0273b42ebafe0ec3546bd645709e7c1b0/pstack/skills/unslop/SKILL.md) and changed it to fit how I write.

Each assistant kept its own copy of the skill in its own folder. Then I found that Copilot had been quietly loading an old backup copy instead of the current file. Both assistants were supposed to edit my writing by the same rules. They weren't, and nothing told me.

## The goal: one editor that every assistant calls

I wanted one copy of the rules and one place that does the editing. [Agent Inbox](https://github.com/shariqh/agent-inbox), my open-source app for running coding agents on my own machine, already lets one agent hand work to another over A2A, a protocol for AI agents to call each other. So I turned unslop into an agent there: a small program that edits text with a language model running on my GPU computer at home. Both assistants now send it their drafts instead of editing by their own copies of the rules.

Sending my drafts from my laptop to that computer meant setting three rules first:

- **Private text stays on my laptop.** A customer email or anything else private must never reach the GPU computer.
- **Facts stay the same.** An edit can change the wording, but not numbers, links, dates, or whether a sentence says "not".
- **Off means off.** The agent stays off until I switch it on, and while it's off, nothing gets sent.

## How I built it

Each of those rules became a piece of code.

Before a draft leaves my laptop, a check looks for signs that it's private: email headers, text laid out like a letter, phone numbers, passwords or keys, and names I've listed as private. If it finds any, it refuses, and the draft stays on my laptop.

After the model sends back its edit, a second check compares the edit with the original. Every number, link and date has to still be there, in the same order, and each sentence has to keep its "not". If the edit fails, the agent tries once more. If that fails too, I get my original text back unchanged. In one test I hid an instruction in a draft telling the model to add a date. The model followed it, and this check caught the new date and returned my original.

The model also treats my draft only as text to edit, never as instructions. Each call wraps the draft between two random marker lines, so a sentence in the draft like "ignore your rules" is just more text to clean up.

A command in Agent Inbox switches the agent on and off.

Last, I split the skill into two files: a short one that tells an assistant when to call the agent, and one file of rules. Copilot, Claude Code and the agent all read that same rules file now, so there's only one copy to keep up to date. That fixed the problem that started all this.

## How the two-week trial went

On November 7 I switched the agent on for my real drafts, as a two-week trial, and it passed. From November 9 to 21, my assistants called the agent 260 times, and 97% of those calls got a result back. Before the trial I set two limits it had to stay under to pass:

- **Failed calls:** 3% of calls failed, and my assistant edited the draft itself instead. The limit was 25%.
- **Original text returned:** 2% of calls gave back my original text unchanged, which is what the agent does when it can't make an edit that passes the fact check. The limit was 15%.

I also planned a blind review of 20 edits to check that they kept their meaning. I never recorded that review, so I can't say how the agent did on it.

Before the trial, I tested the privacy check on 7 private texts. It refused 6 of them. The 7th had no name in it and wasn't laid out like a letter, so the check found nothing to refuse and let it through.

## What's still open

That 7th text is the main gap. Today the check refuses text that looks private, so private text that doesn't look private gets through. I'd rather turn that around: send only text that the check can positively tell is meant to be public, and refuse the rest. I want that fixed before I send more kinds of writing to the agent.

The same setup should work for other skills: check the text before it leaves, keep it apart from the instructions, and check the result. Unslop is the first skill I've moved.

The agent's code is in [Agent Inbox](https://github.com/shariqh/agent-inbox), and the [user guide](https://github.com/shariqh/agent-inbox/blob/main/docs/unslop.md) explains how to turn it on. The [companion post](/blog/a2a-from-scratch) covers the A2A server it runs on.
